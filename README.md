# Monthly Attendance Import — native HRMS v16

Version 0.2.0 records the agreed employee-row N.T/O.T workbook as **standard HRMS Attendance** plus **native Overtime Slip / Overtime Details**. It creates drafts only. It does not submit slips, create Additional Salary or generate payroll payments. Native Overtime Slip submission can create Additional Salary through HRMS; that is a separate payroll action.

This revision is on `native-hrms-overtime`. The `main` branch remains the v15 implementation. Do not install this revision on v15. No Frappe, ERPNext or HRMS core source is changed.

- No legacy Employee Overtime Entry or Additional Salary was generated by the import. Separate `MAI Test ...` companies contain integration-test fixtures.

## Install and rollout

Use a compatible v16 bench, back up database/private files, register this app using normal `bench get-app`/local-app registration, then:

```sh
bench --site your-local-site install-app monthly_attendance_import
bench --site your-local-site migrate
bench build --app monthly_attendance_import
```

Restart web processes so all native Attendance, Leave Application, Shift Assignment and Overtime Slip writers load the serialization hooks. New imports execute immediately in the web request under the initiating user; no import worker or queue is required. Redis remains required by Frappe and progress reporting. Existing jobs queued by earlier app versions retain their compatibility handler. Do not upgrade a shared v15 bench to run this branch.

The app adds its own schemas and workspace; native schemas are unchanged. The workspace is **Monthly Attendance Imports** (plural) so it does not shadow the **Monthly Attendance Import** DocType route. An idempotent pre-model-sync patch renames an older app-owned workspace without changing import records.

Employee Overtime Entry and its result link have been removed. Native Overtime Slip is the only overtime destination. The removal migration refuses to proceed if legacy records or populated audit links exist; those must be reconciled first. No historical records are automatically deleted or converted.

## Supported Excel layout

The user confirmed the reference orientation: employees in paired rows, days across columns. The transposed days-in-rows layout is not supported.

| Location | Content |
|---|---|
| M3 | `MONTH OF -NOV- 2026`, agreeing with the selected period |
| D4 / E4 | Exact `EMPLOYEE NUMBER` / `HOURS` headers |
| F5:AJ5 | Days 1–31; unused invalid-day headers may be blank |
| D6, D8, … | Employee numbers as text, preserving leading zeros |
| E6/E7, E8/E9, … | Exact N.T/O.T pairs |
| F6:AJ7, etc. | N.T numeric hours or a configured code; O.T numeric hours |

Download Template uses the selected period. Insert copies of rows 6–7 above the notes, keeping employee pairs contiguous. Names/categories are informational and never used for matching. Reference integers in General/0 number format are accepted without padding; text is required for zero-padded or long identifiers. Duplicate identifiers or mismatched pairs fail.

For a multi-sheet workbook, enter the exact **Worksheet** name on the batch. Only that sheet is imported using the same fixed layout; this is not a column-mapping engine. The populated October 2026 workbook uses `ALAbraqi`. A changed worksheet invalidates the preview, and Download Template uses the selected worksheet name.

The confirmed October codes are supported explicitly: `P` creates Present with the policy's **Present Hours** (also the threshold for numeric N.T entries); `F` skips Attendance and retains positive overtime when its policy is confirmed; `AB` is configured Absent; `VACATION` requires approved leave. An O.T dash means no overtime, distinct from explicit zero. A code merged across dates within one employee's N.T/O.T pair applies to each covered N.T date and retains the merged source reference. Blank merged ranges remain missing data; merged numeric hours, formulas and cross-employee codes are rejected.

The user-supplied leave types map `VACATION` to **ANNUAL LEAVE** and `SL` to **Sick Leave**, configured as explicit Link fields in the company policy. An approved application of another type cannot satisfy these codes. The local demo also contains the supplied **EMERGENCY** type; EA and UH remain unmapped because their labels alone do not establish which leave type to charge. No allocation or leave approval is created by the importer. The mapping regression suite passes 30 portable tests.

Native leave approval creates submitted On Leave Attendance. The importer reuses it without changes only when the full-day approved application, employee/date/company, type, hours and other relevant values match exactly, and no custom Attendance workflow is active. Other submitted Attendance still conflicts. This exception records an existing native leave result; it does not approve leave or submit Attendance.

When the approved Leave Type excludes holidays, dates on the effective holiday calendar are skipped without creating leave Attendance. Any existing Attendance on those excluded dates requires review. This preserves native leave-day counting (for example, October 2026 has 26 leave days when its five Fridays are excluded). The focused portable suite passes 33 tests.

Leave-reuse verification: 30 portable tests and all 8 database tests passed. An initial database run during simultaneous demo setup encountered a lost savepoint; the isolated rerun passed. Run setup separately from integration tests.

Local demo follow-up: a clearly labelled synthetic annual-leave allocation and approval (`HR-LAP-2026-00001`) now cover October for employee `2605540463`. HRMS created 31 submitted leave Attendance records through its own approval process. Revalidation of `MAI-2026-00004` is **Ready: 1,079 proposed, 347 skipped, zero errors**. The skipped count includes those 31 unchanged leave records. The importer has not posted this batch; its remaining Attendance and Overtime Slip proposals remain available for Import. This test setup is not a production leave entitlement or approval.

The fixed daily range excludes totals from AK onward, notes, signatures and unrelated dates. November 31 and non-leap February 29 must be empty, even of zero. Formulas and Excel errors in daily cells are rejected. Hours must be finite, nonnegative, at most two decimal places, and normal plus overtime cannot exceed 24. Blanks, zeros and codes remain distinct.

Limits: one explicitly selected worksheet per batch, 5 MiB compressed / 30 MiB expanded ZIP, 1,000 ZIP members, 2,000 rows × 80 columns in the selected worksheet, 100 employees. Nothing in its input range is silently truncated.

## Explicit company policy

HR Managers configure and enable one **Monthly Attendance Import Policy** per company. Payroll-sensitive defaults are unset. Required unresolved decisions block affected entries, and any error blocks the whole batch.

Enabled policies now require all core hour/shift/holiday/overtime settings and explicit code choices before saving. Choose Block for unused codes. VACATION Leave Type and SL Leave Type are required only when their respective rule is Approved Leave. Disabled policies can remain incomplete. Both policy saves and import validation enforce these requirements on the server; previously incomplete policies produce one consolidated missing-settings error before employee/day processing. The policy validation regression suite passes 32 portable tests. No policy values are auto-filled by this change.

- Identifier mapping: exact Employee ID (`name`) or `employee_number`; unknown, ambiguous and cross-company identifiers fail.
- Confirm `0 < Half Day < Present <= 24`. Thresholds are inclusive; positive hours below Half Day require manual review. Half Day requires an explicit absent-remainder rule.
- Blank handling: Skip or Block; never absence. Zero handling: Skip, Absent or Block. Blank N.T with explicit O.T zero requires clarification.
- Overtime-only: explicitly Record only or Block; never fabricate Attendance/check-in times.
- Shift: require one effective assignment/default, or explicitly No shift. Multiple assignments and no-shift conflicts are blocked.
- Holidays: effective v16 Holiday List Assignments / Shift Type holiday precedence, with explicit Use daily rule, Skip or Block. Skip cannot discard positive overtime.
- EA, AB, SB, RH, HD, SL, UH, MD: each explicitly Block, Skip, Absent, Approved Leave, Present or Half Day. Approved Leave requires one submitted approved full-day Leave Application. Half-day leave and code-plus-overtime require manual review.
- **Overtime Type**: an existing native type chosen by HR; the importer never creates types, salary components, multipliers or rates. Its maximum daily hours is checked even when an Attendance reference exists.
- **Standard Working Hours**: an explicit positive value up to 24, used in native daily Overtime Details. It is not inferred from normal or overtime hours.

Dates outside active employment or in the future fail. Native Attendance validations remain active; conflicts with approved leave are blocked before native validation can silently change the proposed status.

## Use

1. Open **Monthly Attendance Imports**, then its import list. Create/save a batch with company/month/year.
2. Attach a private `.xlsx` file or download the supported blank template.
3. **Validate & Preview** shows employee/date, source cells, hours/codes, decisions, errors and existing-record links.
4. Correct inputs/policy and preview again. **Import** immediately validates and posts the batch in one atomic request.
5. Reload the batch and follow Attendance / Overtime Slip links. Drafts remain for review; the importer never submits them.

The form includes an import progress bar. While importing it polls a permission-checked status endpoint every two seconds and shows validation, processing entries, overtime and finalization. Counts include entry-processing steps and native overtime slips; they are not committed-record counts. Progress stays below 100% until the committed batch status is Imported. Completed/failed results reload automatically. Progress uses an expiring site-local cache and never commits the business transaction. Cache failures do not change posting; no WebSocket service is required. Leaving the form stops polling. Progress tests and the existing portable suite pass (35 tests); JavaScript syntax is checked.

One native slip is created per employee/month, with one detail per positive-overtime date. Attendance stores normal hours in `working_hours`. Overtime is recorded only in native Slip details; Attendance auto-overtime fields are not populated as a second path. Details link the newly created or identical existing Attendance where applicable. Explicit month boundaries avoid fabricating salary-structure assignments.

Counts are employee-day results, not document counts: a Created result can link both an Attendance and a shared monthly Slip. Source files, batch results, links, actor and preview/import history are retained. New file uploads preserve old attachments. Audit files/batches cannot be deleted through normal APIs.

## Safety, retries and rollback

The server reparses the private file and recomputes policy/employee/workflow/existing-record state at import time. Native overtime type revisions and detail values are fingerprinted. Browser-provided preview rows cannot authorize posting; changes require a fresh preview.

Batch read/write, company access, private File read, Employee read, Overtime Type read and business-document create permissions are enforced. No `ignore_permissions` is used. Disabled initiating users cannot post. Native workflows must start in draft and remain enforced.

Batch/company/policy and sorted Employee locks serialize posting. Current locking reads detect existing records. Native writers also acquire Employee locks. Overtime Slip additionally uses a current locking overlap check before native validation, because its native overlap query alone is not a concurrency lock. Direct SQL writers are outside this contract.

The entire batch is validated before inserts. All Attendance records are inserted first, then grouped native Slips are linked and inserted in the same transaction. Failure rolls back all new records and links; actionable failure history is retained. Identical initial drafts can be skipped only when relevant values, type, standard hours, period, references and workflow state match. Changed/submitted records and overlapping slips conflict; nothing is overwritten. Re-uploading no overtime over existing monthly overtime is a conflict.

On failure, correct the cause and preview again. Keep the form open until the immediate request finishes. For a connection or request timeout, reload the batch before retrying: the committed status is authoritative, and an imported batch cannot post twice. Synchronous imports are subject to web-server/proxy request timeouts; removing queue wait does not remove document validation or database work. Earlier queued jobs must finish or be recovered via Validate & Preview after their job ends. Do not run site-specific hooks that commit midway or perform irreversible side effects during insertion.

Operational rollback: disable policies and drain jobs; keep the app installed so audit links remain readable. Uninstall would destroy app audit tables and requires a separate approved retention/migration plan. No destructive contraction is performed here.
